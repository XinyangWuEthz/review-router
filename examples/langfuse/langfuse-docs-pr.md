# Pull request text for langfuse/langfuse-docs

Title: `docs: add cookbook on prioritizing traces for human annotation under a fixed budget`

Body:

---

Adds `cookbook/example_annotation_queue_prioritization.ipynb` and its generated
guide page.

**What it covers.** Annotation queues are easy to fill; the scarce resource is
the reviewers' time. The cookbook takes a per-run review budget and the
automated scores already on a project's traces (LLM-as-a-judge, code checks,
user feedback), compares five selection policies on the same candidate pool
(`random`, `max_score`, `severity`, `uncertainty`, `mixed`), pushes one of them
into an annotation queue through the Public API in priority order, and reads
the `ANNOTATION`-source scores back to estimate each policy's hit rate and the
judge's agreement with humans. Every table shows the displaced work next to the
gain: selection under a budget reallocates reviewer time, it does not add any.

Two of the policies mirror arms of the
[review-router](https://github.com/XinyangWuEthz/review-router) benchmark
(probability ordering and severity ordering); the other three are additions for
annotation queues and are labelled as such in the text.

**How it is built.**

- Runs end to end without credentials on a synthetic pool with hidden ground
  truth, so the stored outputs are reproducible; with credentials it reads and
  writes the project.
- Reads scores through `GET /api/public/v3/scores` (`api.scores_v3.get_many_v3`,
  cursor pagination, `subject,annotation,details` field groups), not the
  deprecated v2 endpoint.
- Writes the selection decision on each trace as a categorical score with
  metadata, so a later run can attribute the human labels to policies without
  the first run's memory.
- Tables are emitted as Markdown so the generated MDX renders them.
- The selection logic is a single self-contained cell; the same code lives in
  the review-router repository with a test suite that keeps the two copies in
  sync.

**Validation.** Tested with `langfuse` 4.17.0 on Python 3.12/3.13. Offline
execution with nbclient reproduces the stored outputs. Two live runs against a
Langfuse Cloud project seeded with 300 synthetic traces confirmed: candidate
pool built from v3 scores with trace ids resolved from `subject`; score configs
and queue created from plain-string arguments; 40 items added in rank order and
served in that order; the categorical `review_policy` score and its metadata
read back through the `details` group; after scoring ten items in the UI, the
second run excluded them, added a second batch, and rebuilt the per-policy
precision and judge-agreement tables from the stored decisions. Duplicate queue
items are not rejected by the API, so the notebook de-duplicates before adding.
No real credentials or project data are in the notebook.
